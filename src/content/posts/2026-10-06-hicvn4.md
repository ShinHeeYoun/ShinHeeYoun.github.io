# Tomcat 10 (Jakarta EE) 라이브러리 마이그레이션 도구 설명서

## 1. 개요

### 1.1 목적
Tomcat 9 이하 환경에서 사용하던 `javax.*` 기반 라이브러리(jar)를 Tomcat 10 이상에서 사용하는 `jakarta.*` 기반으로 변환한다. 이 문서는 변환 도구의 사용 방법과 동작 방식, 그리고 변환 결과를 Tomcat 10에 적용하고 설치 상태를 확인하는 절차까지 정리한다.

### 1.2 변환이 필요한 이유
Tomcat 10부터 Java EE가 Jakarta EE로 이전되면서 패키지 이름이 `javax.servlet.*` 에서 `jakarta.servlet.*` 로 바뀌었다. 기존 jar가 `javax.*` 를 참조하면 Tomcat 10에서 `ClassNotFoundException`, `NoClassDefFoundError` 가 발생한다.

### 1.3 문서 범위
| 구분 | 내용 | 도구가 수행하는지 |
|---|---|---|
| 계정 준비 | Tomcat 실행/작업용 계정 생성 | 아니오 (수동) |
| 환경 준비 | Java 설치 확인 | 아니오 (수동) |
| 라이브러리 변환 | jar 내부 `javax` 를 `jakarta` 로 변환 | 예 |
| 결과 확인 | 로그 및 파일 점검 | 부분 (로그 생성) |
| Tomcat 반영 | 변환된 jar 배포 | 아니오 (수동) |
| 설치 확인 | Tomcat 버전 및 기동 확인 | 아니오 (수동) |

계정 생성, Java 확인, Tomcat 반영과 설치 확인은 아래 도구에 포함되어 있지 않으며, 이 문서에서 절차만 안내한다.

## 2. 구성 파일

작업 폴더: `D:\storageD\110_2) TOMCAT_10 MIGRATION 방법\`

| 파일 | 역할 |
|---|---|
| `Run_Migration_Tool.bat` | 실행 진입점. PowerShell 스크립트를 호출한다. |
| `Tomcat_Migration_Tool.ps1` | 폴더 선택과 실행 버튼을 제공하는 GUI. 변환 jar를 호출한다. |
| `jakartaee-migration-1.0.12-shaded.jar` | 실제 변환을 수행하는 Apache Tomcat Migration Tool for Jakarta EE (1.0.12). 의존 라이브러리가 하나로 묶인(shaded) 실행 가능 jar. |
| `lib_beforeMig\` | (예시) 변환 전 라이브러리 폴더 |
| `lib_migrated\` | (예시) 변환 후 라이브러리 폴더. `migration_log.txt` 가 함께 생성된다. |

세 파일(`.bat`, `.ps1`, `.jar`)은 반드시 같은 폴더에 있어야 한다.

## 3. 사용방법

### 3.1 계정 준비
1. Tomcat을 실행하고 변환 작업을 수행할 전용 계정을 생성한다. 관리자 권한이 필요 없는 일반 계정을 권장한다.
2. 해당 계정에 다음 권한을 부여한다.
   - 작업 폴더(`D:\storageD\110_2) TOMCAT_10 MIGRATION 방법\`): 읽기, 쓰기
   - Tomcat 설치 폴더: 읽기, 실행 (배포 시 `webapps` 또는 `WEB-INF\lib` 쓰기)
3. 생성한 계정으로 로그인한다.

### 3.2 Java 설치 확인
변환 도구는 `java` 명령을 PATH에서 찾아 실행한다.

1. 명령 프롬프트를 열고 다음을 실행한다.

   ```
   java -version
   ```

2. 버전이 출력되면 정상이다. 명령을 찾을 수 없다는 메시지가 나오면 JDK/JRE를 설치하고 `JAVA_HOME` 및 PATH를 설정한다.
3. 변환 도구는 Java 8 이상에서 동작한다. 배포 대상이 Tomcat 10.1 이면 Java 11 이상이 필요하다.

### 3.3 변환 대상 준비
1. 변환할 jar 파일들을 하나의 폴더에 모은다. (예: `lib_beforeMig`)
2. 원본 폴더는 변환 중 수정되지 않지만, 안전을 위해 별도로 백업해 둔다.
3. 출력 폴더는 원본과 다른 경로로 정한다. (예: `lib_migrated`) 존재하지 않으면 자동 생성된다.

### 3.4 도구 실행
1. `Run_Migration_Tool.bat` 를 더블클릭한다.
2. "Tomcat 10 (Jakarta EE) Migration Tool" 창이 열린다.
3. `Source Lib Directory` 의 `Browse...` 를 눌러 변환 전 폴더를 선택한다.
4. `Destination Directory` 의 `Browse...` 를 눌러 출력 폴더를 선택한다.
5. `Run Migration` 버튼을 누른다.
6. 처리 중에는 버튼이 비활성화된다. 완료되면 완료 메시지 창이 표시되고, 상태 창에 로그가 출력된다.

### 3.5 결과 확인
1. 출력 폴더의 `migration_log.txt` 를 연다.
2. 마지막 줄이 `Migration completed successfully in [...] milliseconds` 인지 확인한다.
3. 로그에 `ERROR`, `Exception`, `Unable` 등 오류 문구가 없는지 검색한다.
4. 입력 폴더와 출력 폴더의 jar 파일 개수가 같은지 비교한다.

### 3.6 Tomcat 10 반영
1. Tomcat 10을 중지한다.
2. 변환된 jar를 애플리케이션의 `WEB-INF\lib` 또는 Tomcat의 `lib` 폴더에 복사한다. 기존 변환 전 jar는 제거한다.
3. 애플리케이션 자체의 코드와 설정(`web.xml`, 소스의 `javax.servlet` 등)도 `jakarta` 기준으로 변환되어 있어야 한다. 이 도구는 라이브러리 jar만 변환한다.
4. 필요하면 `<Tomcat>\webapps` 대신 `webapps-javaee` 폴더에 두어 Tomcat 자체 변환 기능을 이용하는 방법도 있다. (이 도구와는 별개의 방법이다.)

### 3.7 Tomcat 설치 확인
1. 버전 확인

   ```
   <Tomcat 설치경로>\bin\version.bat
   ```

   출력의 `Server version` 이 `Apache Tomcat/10.x.x` 인지 확인한다. `JVM Version` 도 함께 확인한다.

2. 기동

   ```
   <Tomcat 설치경로>\bin\startup.bat
   ```

3. 기동 로그 확인: `<Tomcat 설치경로>\logs\catalina.<날짜>.log` 에 `Server startup in [...] milliseconds` 가 있는지 확인한다.
4. 접속 확인: 브라우저에서 `http://localhost:8080/` 에 접속하여 Tomcat 기본 페이지 또는 애플리케이션 화면이 표시되는지 확인한다.
5. 오류 확인: `catalina.<날짜>.log` 와 `localhost.<날짜>.log` 에 `ClassNotFoundException`, `NoClassDefFoundError`, `javax.` 관련 오류가 없는지 확인한다.
6. 기능 확인: 메일 발송, SOAP(Axis2), 스케줄러(Quartz), 리포트 등 변환된 라이브러리를 사용하는 기능을 실제로 호출해 본다.

## 4. 기술 설명

### 4.1 전체 동작 흐름

```
Run_Migration_Tool.bat
   └─ powershell -File Tomcat_Migration_Tool.ps1
        └─ (Run Migration 클릭) cmd /c java -jar jakartaee-migration-1.0.12-shaded.jar <source> <dest> > <dest>\migration_log.txt 2>&1
             └─ 종료 코드 확인 후 결과 표시
```

### 4.2 Run_Migration_Tool.bat
| 항목 | 내용 |
|---|---|
| `@echo off` | 실행 명령 출력을 끈다. |
| `powershell -ExecutionPolicy Bypass` | 이번 실행에 한해 스크립트 실행 정책을 우회한다. 시스템 설정은 변경하지 않는다. |
| `-WindowStyle Hidden` | PowerShell 콘솔 창을 숨긴다. GUI 창만 표시된다. |
| `-File "%~dp0Tomcat_Migration_Tool.ps1"` | `%~dp0` 는 bat 파일이 위치한 폴더이다. 어느 경로에서 실행해도 같은 폴더의 ps1을 찾는다. |

### 4.3 Tomcat_Migration_Tool.ps1
1. 초기화
   - Windows Forms, Drawing 어셈블리를 로드한다.
   - 스크립트와 같은 폴더에서 `jakartaee-migration-1.0.12-shaded.jar` 를 찾는다. 없으면 오류 메시지를 표시하고 종료한다.
2. 화면 구성
   - Source 경로 입력란과 Browse 버튼
   - Destination 경로 입력란과 Browse 버튼
   - Run Migration 버튼
   - 읽기 전용 상태 창
3. 실행 전 검사
   - Source 또는 Destination이 비어 있으면 경고 후 중단한다.
   - Source 폴더가 존재하지 않으면 오류 후 중단한다.
   - Destination 폴더가 없으면 생성한다.
4. 변환 실행
   - `cmd.exe /c java -jar "<jar>" "<source>" "<dest>" > "<dest>\migration_log.txt" 2>&1` 를 콘솔 창 없이 실행한다.
   - 표준 출력과 표준 오류를 모두 `migration_log.txt` 로 저장한다.
   - 실행 중 `DoEvents()` 와 100ms 대기를 반복하여 화면이 멈추지 않도록 한다.
5. 결과 판정
   - 프로세스 종료 코드가 0이면 성공, 그 외는 실패로 표시한다.
   - 로그 파일을 시스템 기본 인코딩으로 읽어 상태 창에 출력한다.
6. 예외 처리
   - 프로세스 시작 자체가 실패하면 Java 설치 여부를 확인하라는 메시지를 표시한다.
   - Java가 PATH에 없는 경우에는 `cmd` 가 오류 코드를 반환하므로, 실패 메시지와 로그 파일의 `java` 인식 오류 문구로 확인한다.

### 4.4 jakartaee-migration-1.0.12-shaded.jar
Apache Tomcat 프로젝트의 Jakarta EE Migration Tool이다. 이 스크립트는 `<source>` `<dest>` 두 인자만 전달하므로 기본 설정으로 동작한다.

| 항목 | 동작 |
|---|---|
| 프로파일 | 기본값 `TOMCAT`. 로그 첫 줄에 `Jakarta EE specification profile [TOMCAT]` 로 표시된다. |
| 입력이 폴더인 경우 | 폴더 안의 파일을 처리하여 출력 폴더에 저장한다. jar는 변환하고, 변환 대상이 아닌 파일은 그대로 복사한다. |
| 변환 내용 | 클래스 파일의 바이트코드와 텍스트 리소스에 포함된 `javax.*` 패키지 참조를 `jakarta.*` 로 치환한다. 대상은 Servlet, JSP, EL, WebSocket, Mail, Activation, JMS, XML Binding 등 Jakarta EE 명세 패키지이다. |
| 제외 대상 | 기본 제외 목록에 있는 jar(`asm`, `bcprov`, `bcpkix`, `slf4j-api` 등)는 변환하지 않고 그대로 복사한다. 로그에 `excluded (the archive was copied unchanged)` 로 표시된다. |
| 처리 방식 | 스트리밍 방식(`using streaming`)으로 jar를 읽으며 변환하여 메모리 사용을 줄인다. |
| 중첩 jar | jar 안에 포함된 jar도 재귀적으로 변환한다. |
| 서명 파일 | jar 내용이 바뀌면 기존 서명이 무효가 되므로 `META-INF/*.SF`, `*.RSA`, `*.DSA` 를 삭제한다. 로그에 `Drop cryptographic signature file` 로 표시된다. |
| 종료 코드 | 정상 완료 시 0, 오류 시 0이 아닌 값 |

### 4.5 로그 메시지 해석
| 로그 | 의미 | 조치 |
|---|---|---|
| `Migration starting for archive [...]` | 해당 jar 처리 시작 | 없음 |
| `Migration finished for archive [...]` | 해당 jar 처리 완료 | 없음 |
| `Migration skipped ... because it is excluded` | 제외 대상으로 변환 없이 복사 | 없음 |
| `Drop cryptographic signature file [...]` | 서명 파일 삭제 | 없음 |
| `Migration completed successfully in [N] milliseconds` | 전체 정상 종료 | 없음 |
| 그 외 `ERROR`, `Exception` 등 | 변환 실패 | 해당 jar 확인 |

로그에 표시되는 경로의 한글이 깨져 보일 수 있다. 이는 로그 파일 인코딩 문제이며 변환 결과에는 영향이 없다.

## 5. 제약 사항 및 주의사항

1. 변환 성공은 도구가 오류 없이 끝났다는 의미이며, 변환된 라이브러리가 Tomcat 10에서 정상 동작한다는 보증이 아니다. 반드시 3.7절의 기동 및 기능 확인을 수행한다.
2. 문자열을 조합하여 만든 클래스 이름(리플렉션), 설정 파일 내 참조 등은 변환되지 않을 수 있다.
3. 오래된 라이브러리(예: Axis2 1.7.0, Axiom 1.2.13, JAXB API 2.1, Mail, Activation, Geronimo JMS)는 변환해도 정상 동작하지 않을 수 있다. 가능하면 Jakarta를 정식 지원하는 최신 버전으로 교체한다.
4. 서명이 삭제된 jar는 서명 검증이 필요한 환경에서는 사용할 수 없다.
5. 출력 폴더를 입력 폴더와 동일하게 지정하지 않는다.
6. `migration_log.txt` 는 출력 폴더에 함께 생성되므로 배포 시 jar만 선별하여 복사한다.
7. 변환 도구는 라이브러리만 변환한다. 애플리케이션 소스, `web.xml`, 기타 설정 파일은 별도로 점검한다.

## 6. 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| `Migration jar file not found` 메시지 | ps1과 같은 폴더에 jar가 없음 | 세 파일을 같은 폴더에 둔다. |
| `Migration failed with exit code` 표시 | Java 미설치 또는 PATH 미설정, 변환 오류 | `java -version` 확인 후 `migration_log.txt` 를 확인한다. |
| 로그 파일이 비어 있음 | `java` 명령을 찾지 못함 | Java를 설치하고 PATH를 설정한다. |
| 실행 시 창이 열리지 않음 | PowerShell 실행 제한 또는 보안 프로그램 차단 | 명령 프롬프트에서 bat을 실행하여 오류를 확인한다. |
| Tomcat 기동 시 `NoClassDefFoundError` | 변환 누락 또는 일부 jar가 변환 전 상태로 남아 있음 | 변환 전 jar가 배포 위치에 남아 있는지 확인한다. |
| Tomcat 기동 시 `UnsupportedClassVersionError` | Java 버전이 Tomcat 요구 버전보다 낮음 | Tomcat 10.1은 Java 11 이상을 사용한다. |
